## Done (the package)
- **1. Engine profiles** (`src/narration/engine/profile.py`, `models.py`):
  - `build_profile(config, kind)` for `qwen3-base-1.7b.pN` and `qwen3-design-1.7b.pN`. It is built from the
    config, the snapshot and the Qwen worker's `uv.lock`:
    - the model pins (`models.PINNED`);
    - every snapshot file's sha256, cached by `FileHashes`;
    - the lock's sha256, and the locked versions of `QWEN_PACKAGES`;
    - the ten sampling values of `generation_config.json`, all required (no library defaults, §10.1);
    - the determinism switches and the DC-4 cap rule.
  - Its hash is `keys.hash_key` over `hashed_object`: every field except `UNHASHED` (`hash`, `snapshot_dir`,
    `observed`, `tier`, `canary`, `vram_need_mb`).
  - `current_profile`, `current_ref` and `require_expected` are for WP33 and WP36. `require_expected` raises
    `ENGINE_CHANGED` with `field` = `expect_engine_profile`.
  - A snapshot with an unfinished download (`*.partial`) is refused at the pin (`BACKEND_NOT_INSTALLED`), and
    is never hashed.
- **2. The fingerprint check** (`drift.py`) runs after every Qwen load. It compares the hello's package
  versions and `CUBLAS_WORKSPACE_CONFIG`, the lock's sha256 and every snapshot file with the profile.
  - Any difference is `ENGINE_DRIFT` (not retryable), and `details.drift` lists each one.
  - An unfinished download is drift of its own kind, `download`.
- **3. `installed_engine(host)`** (`engine/installed.py`) returns a `Registry`. It holds WP15's `CtcAligner`,
  the QA pins with their licences, `CanaryGuard` and the NVML probe.
  - It also holds WP33's `measure` handler.
  - A missing snapshot, or an `[alignment]` the engine cannot run, is `BACKEND_NOT_INSTALLED`.
- **4. The QA group's VRAM need** (`engine/qa.py`): `QA_VRAM_NEED_MB = 11_500`, from WP22's spike h. The
  configuration it was measured with is pinned by `tests/engine/test_qa_need.py`.
- **5. `narration-admin engine pin | repin [--force] | bridge | show`** (`engine/pinning.py`,
  `engine/admin.py`), registered through WP37's dispatcher. Workers start through WP30's `WorkerSupervisor`,
  exactly as the daemon starts them. `pin`:
  - designs the canary on this machine (DC-3);
  - runs the repeat test (three renders, one in a fresh process; ADR 0002);
  - calibrates each threshold with 3 more seeds;
  - stores the clip under `engines/<id>/canary.wav`.
- **6. The canary gate** (`engine/canary.py`, `CanaryGuard.after_load`) runs these checks in order:
  - drift;
  - the canary material's id;
  - the pinned embedding's validity;
  - the gate render. Then:
    - an equal hash → `hash_match`;
    - otherwise WavLM-SV alone on the QA worker's CPU, unloaded afterwards → `similarity_pass`, or
      `ENGINE_DRIFT` below the threshold.
- **7. The daemon passes the aligner's method id** to its store (an authorised change in WP30's
  `__main__`).

## Decisions made (and why)
- **The threshold is calibrated, then floored.** It is the lowest similarity of 3 more seeds, less 0.01,
  and never below 0.10 (ASSUME: a gate below it would pass almost any voice).
- **The machine is compared only on `repin`.** `pin` never replaces a pin, so it never needs to see the
  machine. `repin` needs one Qwen worker start to see it, even when nothing else changed.
- **A moved models root is an in-place update, not a new pin**, because `snapshot_dir` is unhashed and the
  files are the same (the fingerprint check proves it at the next load).
- **The canary's material id** is kept in the `CanaryPin`. Changed canary text is drift at the gate.
- **The pin's workers go through the daemon's supervisor**, so the canary is rendered as the daemon renders.
- **`engine show` creates no store.** `pin`, `repin` and `bridge` hold the daemon's singleton throughout.

## Contract change requests
- **`CanaryPin` has no room for the calibration** (the review asked to record the clamping "if the contract
  has room"). It has none, so no field was invented. Proposed: `CanaryPin.calibration: tuple[float, ...] =
  ()`, the similarities the threshold came from. The flag would then be derived from them, and
  `engine show` could print them. Until then, `floored()` derives the flag from the threshold alone.
- DC-16 is applied (above).
- Other hashed fields that change no audio (listed earlier, not changed): `licence`, `capabilities`,
