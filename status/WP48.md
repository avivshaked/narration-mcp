## Done
- **`narration-admin failures [--since] [--job] [--voice] [--code] [--json] [--export <dir>]`**
  (`src/narration/admin/failures.py`, registered last in `COMMAND_GROUPS`):
  - Lists every take of a `generate` or `analyse` job that **failed QA** (verdict `fail`) or that **a retake
    replaced**, newest job first (the store's queue order, reversed), then in the request's order, slot by
    slot.
  - For each: job id, kind, status and creation time; the voice clip's sha256; segment id, attempt, seed,
    round and `fresh`; take, render and analysis ids; the delivery WAV's path, sha256, length and whether the
    file is there; each **fail and warn** flag (code, severity, message, cue, details) of its analysis, each
    once; the analysis's QA metrics and thresholds as they are (so WP47's pace fields appear when they
    land); the take that finally filled the slot (attempt, take id, verdict); the segment's text as the
    request sent it (cues joined as §7.2 joins them). The text is printed and exported, never logged.
  - **One rule for "replaced" and "final"**, shared with the job report through
    `narration.qa.report.replacements`: an attempt counts as replaced only when a later attempt of its slot
    has a take (take and render in the store, with their files), and the final take is the slot's last
    attempt that has one. A retake whose render failed replaces nothing.
  - Filters: `--since` (ISO date or time, UTC unless it names a zone; the job's `created_at`), `--job`
    (checked against the job id grammar), `--voice` (the request's `voice.sha256`, or a prefix, any case),
    `--code` (upper-cased; one of `ANALYSIS_CODES`, the 16 fail/warn codes QA and the aligner raise; any
    other code is refused with that list). Each bad value is exit 2 with what to give instead. An unknown
    job is exit 1 and says why it may be gone.
  - Human-readable by default; `--json` prints `narration.failures/v1`, described by `FAILURES_JSON_SCHEMA`
    (JSON Schema 2020-12, no `$ref`).
  - **Never writes to the store.** Jobs come from `NarrationStore.iter_jobs` (a cursor, filtered by kind and
    roughly by `--since` in SQL); takes, renders and analyses from the new `peek_render`/`peek_take`/
    `peek_analysis`, which return the record and whether its file is there and never repair the index. A
    take whose WAV was deleted by hand is listed with "wav: file not in the store (<path>)" and no claim
    about the cause.
- **`--export <dir>`**: `<take_id>.wav` (streamed, sha256 checked while copied), `<take_id>.json` (every
  listing of that take; its `wav` is the bundle's own file name, never a store path) and `index.csv` (one
  row per listing, `INDEX_COLUMNS`; UTF-8 with a BOM; a text cell starting with `= + - @`, a tab or a CR gets
  a `'` in front, the sidecars keep the exact text). Every take id is checked with `names.is_id` before it
  names a file, and each resolved target must sit directly in `<dir>`. Every name is checked first:
  identical bytes are left alone (a repeat export is a no-op); a different file refuses the whole export
  before anything is written. A `<dir>` that is the store or inside it is refused: by name, after
  `realpath`, or when an existing ancestor `os.path.samefile`s the store root (a UNC path back to this
  machine). A folder that cannot be created, a file that cannot be read for the pre-check, or one that
  cannot be written is an `AdminError` naming the path and the OS's reason, and saying what to do ("the
  files already written are complete; export again into the same folder to finish").
- **The report's "Failures" section** (`src/narration/qa/report.py`): between "Listen first" and "Segments",
  each failed or replaced take with its fail and warn flags and the take that filled its slot. No path.
  `report_json` gains the same list under `failures`.
- **`gc`** (`src/narration/admin/gc.py`): the dry run, the real run and `--json` (key `failures`) show the
  failed or replaced takes apart: how many are in the store, the oldest's age, which this run takes out of
  the audit (`due`: the take removed, or every job that lists it), and which would only lose their flags and
  metrics (`lose_analysis`: an analysis goes, the take and a job stay). The list is read before the
  collection, with the non-repairing reads, so a dry run changes nothing even where a file is missing. What
  gc removes is unchanged. If the list cannot be read (`NarrationError`, `ValueError`, `OSError`,
  `sqlite3.Error`), gc warns and goes on.

## Decisions made (and why)
- **Store reads for operator views** (WP12's file): `iter_jobs` (replaces this WP's earlier `list_jobs`)
  and `peek_render`/`peek_take`/`peek_analysis`. The store's other readers drop a row whose file is gone
  (a write); an audit must not. Easy to rename if WP12's owner prefers.
- **"Byte for byte" (KNOW, measured 2026-09-28 with a scratch SQLite script):** opening `NarrationStore`
  runs its idempotent migration in a write transaction, and SQLite bumps the change counter in the database
  header even with no row changed. So the tests compare every other file byte for byte (with mode bits) and
  the database row for row (`iterdump`) or by row counts.
- **Export naming by take id**, not by segment id: segment ids are the caller's (`con` would be a bad
  Windows file name), and a take listed by two jobs is one WAV.
- **`--since` is the job's creation time**: a take has no time of its own in its record. The SQL filter on
  `inserted_at` (the store's clock) takes a day of slack; the exact filter is on `created_at`.
- **The schema id `narration.failures/v1` lives in `narration.admin.failures`**, not in contracts: it is
  operator output, not a record or a tool. The lead may move it to `contracts.names`.
