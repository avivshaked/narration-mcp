## Known gap (not fixed here)
- GitHub's hosted Windows runner never exercises the success path of a detached start: its own job forbids
  breakaway, so every survival test takes the refusal branch there. A regression that refused every
  detached start would stay green in CI; only a run on a Windows developer's machine (a host whose jobs
  allow breakaway) catches it. The new warning makes the branch visible; it does not close the gap.

## Decisions made (and why)
- The mismatch text lives in `narration.config`, which the daemon's entry point already imports before
  numpy, so doctor and the daemon say the same thing.
- The end line is written from `EngineRunner._done`, the one place every ending passes through, by
  reading the job's record once: it covers every handler (generate, analyse, measure, later kinds).
  A job the daemon's sweep or `return_job` cancels outside the runner already gets `return_job`'s line.
- "Segments" is `progress.segments_total`; "retakes used" is the sum of the items' `retakes_used`.
