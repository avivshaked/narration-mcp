## Done
- Phase 1:
  - `narration.config.qa_profile_mismatch`: what to say when `[qa] profile` differs from
    `names.QA_PROFILE` (the key is inert; the scorer uses the build's profile). `doctor` reports the
    profile the service scores with (`qa`, ok), or a warning saying which profile runs and to update the
    line; never a failure. The daemon logs the same warning once at start (`warn_on_qa_profile`).
  - `EngineRunner` logs one INFO line when a job it held ends (completed, failed or cancelled): job id,
    kind, final status, outcome, segments, retakes used, wall time since it took the job. A job given back
    to the queue gets no line. Nothing of the request is logged. The clock is injectable (`clock=`).
  - `tests/keys`: the DC-19 test pins `delivery_key` by value (computed on main a901bf9; equal to the
    golden `DELIVERY_KEY`).

## Decisions made (and why)
- The mismatch text lives in `narration.config`, which the daemon's entry point already imports before
  numpy, so doctor and the daemon say the same thing.
- The end line is written from `EngineRunner._done`, the one place every ending passes through, by
  reading the job's record once: it covers every handler (generate, analyse, measure, later kinds).
  A job the daemon's sweep or `return_job` cancels outside the runner already gets `return_job`'s line.
- "Segments" is `progress.segments_total`; "retakes used" is the sum of the items' `retakes_used`.
