## Decisions made (and why)
1. **The fake lives in `narration_worker`, standard library only.** It then runs from the server venv
   (CI), from both worker venvs, and through the real entry point (`-m narration_worker --role fake`).
   It writes the float32 WAV header by hand; a server test checks that soundfile reads it identically.
2. **How the fake's "ears" find their text.** QA runs on the *delivery* file (§11.1), which
   post-processing writes elsewhere. A sidecar next to the raw file would never be found there. Instead,
   every 50 ms segment's pitch (120 + 1.5·k Hz) carries one byte of a 32-bit utterance id, and a
   registry under `<store>/scratch/fake/` maps ids to records. KNOW
   (`workers/common/tests/test_fake.py`, `tests/workers/test_fake_outputs.py`): the id survives 48 kHz
   and 44.1 kHz resampling, gain, trimming, fades and PCM_24/PCM_16. The worst pitch error was
   0.006 Hz against a 0.45 Hz tolerance. The audio is integer arithmetic, so it is bit-identical on
   every platform.
3. **The fault control is the env var `NARRATION_FAKE_SPEC`**, which names a JSON file. The file is
   re-read when it changes, and strictly validated; an invalid spec stops the worker at start with
   exit 2. No request member, MCP input or store content can set it; a test checks that a request
   carrying `faults` plants nothing. `times` counters are marker files in the store, shared across
   processes, so a `crash` with `times: 1` does not crash the restarted worker too.
4. **stdout guard: KNOW** (the `stdout_noise` fault test). On Windows, `os.dup2(2, 1)` also moves the
   process's standard output handle: a child process's `print` lands on stderr, not in the protocol
   pipe. stdin is taken too, so a library that prompts reads EOF instead of a request.
5. **Workers confine paths to `--store`**: inputs and outputs must be absolute and inside the store,
   or the reply is `INVALID_REQUEST`. This is a second guard behind §17.2's server-side checks.
6. **Role resolution:** `fake` is built in. Real roles register an entry point in the group
   `narration_worker.roles`, named after the role; `--handler module:Class` overrides it.
7. **Client failures.** A spawn failure, a missing venv Python, or a role or protocol mismatch in
   `hello` raise `WorkerFailure("BACKEND_NOT_INSTALLED")` (§14: "worker env missing"). A protocol
   break (non-JSON, no id, an unknown id) is `WorkerCrashed`, and the client kills the worker.
   `request` returns the whole reply, `id` and `ok` included. A crash is reported when stdout
   closes; if a grandchild keeps stdout open, it is reported within 0.25 s of the process exiting
   plus a 5 s grace. It is never waited out to the request's timeout.
8. **`worker_env`** always forces `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1`. It keeps a
   configured `CUBLAS_WORKSPACE_CONFIG` and defaults it to `:4096:8`. It sets the thread-cap
   variables, UTF-8 and unbuffered I/O, and drops `PYTHONPATH`, `PYTHONHOME`, `VIRTUAL_ENV`,
   `PYTHONSTARTUP` and `PYTHONSAFEPATH`, so the server's Python cannot leak into a worker venv.
9. The fake's `load` defaults `max_new_tokens` to 8192 (plan.md §1.3). A lower cap, or the
   `token_cap` fault, cuts the take at a segment boundary and sets `hit_token_cap`.
10. The fake transcribes only audio it rendered, or a file listed in the spec's `transcripts` (by
    sha256); anything else gets `UNSUPPORTED_AUDIO`. Its `embed`, `f0`, `align` and `profile` answer
    for any WAV.

## The worker-loop API (for WP20 and WP22; stable from here)
- Subclass `narration_worker.handler.WorkerHandler`. Set `role` (`"qwen3"`/`"qa"`),
  `fingerprint_packages` (e.g. `("qwen-tts", "transformers", "accelerate", "torchaudio")`), and
  `controls` (qwen3). Implement `op_<name>(self, request) -> dict` for every op of the role except
  `hello` and `shutdown`. Return the reply members without `id`/`ok`.
- Fail with `raise OpError(code, message, details)` (`narration_worker.errors`). Validate members with
  `require_str/bool/int/number/str_list/one_of`, and paths with `self.input_file`,
  `self.output_file` and `self.output_dir`.
- Keep the contract in `handler.py`'s docstring: `NOT_LOADED` before `load`, checked before any file
  is read; `load` checks snapshot dirs first (`BACKEND_NOT_INSTALLED`).
- Get torch with `self.torch()`, which applies the thread cap. In `load`, call
  `apply_determinism(parse_determinism(request["determinism"]), self.torch())`. Per render, call
  `seed_everything(seed, torch=self.torch())`. Release models in `shutdown()`. CUDA OOM becomes
  `GPU_OOM` by itself (`classify`).
- Register the handler class: `[project.entry-points."narration_worker.roles"] qwen3 = "pkg.mod:Class"`.
  **Note:** `workers/qwen3tts` and `workers/qa` are `package = false` today, so their entry points will
  not be installed. WP20/WP22 need to make them packages, or the lead needs to decide another route.
- Contract tests: `class TestQwen3WorkerContract(WorkerContract): role = "qwen3"` in the worker's tests,
  run from its venv. Override the `load_request` fixture to include the load round trip.

## Contract change requests
- **`narration_worker/protocol.py`: drop `from __future__ import annotations`.** With postponed
  annotations, `TypedDict` cannot see `NotRequired`, so at run time every key counts as required.
  KNOW: `Reply.__required_keys__ == {'error', 'id', 'ok'}`, `AudioReply.__optional_keys__ == set()`,
  and `Capabilities` lists `controls` as required. Type checkers are unaffected. Runtime checks
  (conformance tests, a validator) get them wrong. BELIEVE the import can simply go: every name is
  defined before use and all annotations are valid at 3.12 run time. Local adapter:
  `tests/workers/test_fake_outputs.py::_required` reads `get_type_hints(include_extras=True)`
  instead.

## Dependency requests
- none. (Optional, for WP20/WP22: `nvidia-ml-py`, BSD-3-Clause, in a worker venv would let `hello`
