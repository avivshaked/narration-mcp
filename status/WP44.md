State: review        Updated: 2026-09-28T19:30Z

the code. It does not cover the clean-machine install test, `doctor` on a machine with no GPU, the version and
CHANGELOG for a release, or the GitHub description. The work ran in a cloud sandbox with no GPU, no models, no

## Decisions made (and why)
- S1: the WAV check moved before the sha256 check, instead of dropping `details.actual` everywhere. A caller
  still gets the hash of a WAV it named (useful, and `profile_voice` measures that file anyway), but never the
  hash of any other file. At job time (`stage_clip`) the file is no longer the one admitted, so the hash is not
  given at all. A caller who names a file that is not a WAV now gets `UNSUPPORTED_AUDIO` instead of
  `VOICE_FILE_MISMATCH`, which is also the more useful answer.
- S2: `find_program` lives in `narration.platform` (the place for OS behaviour). It skips empty and relative
  `PATH` entries, which also closes the POSIX form of the same issue.
- The model licences are all BELIEVE: huggingface.co (and its mirrors) could not be reached from the sandbox,
  so no model card was read. I did not write any of them as KNOW.

## Questions for the lead / owner
- **LGPL** (needs your OK, AGENTS.md rule 9):
  - `soundfile`'s wheels bundle libsndfile (LGPL-2.1, with LAME and mpg123), in the server and both workers.
  - `soxr` (LGPL-2.1-or-later) comes into both workers through `librosa`. plan.md DC-1 already accepts it.
  - `pywin32`'s unused `adodbapi` sub-package is LGPL; it comes into the server through `mcp`, on Windows.
- **MPL-2.0** is not named in the policy: `certifi`, `tqdm` and `orjson` (workers only). Is weak copyleft
  acceptable when the code is used unmodified?
- **NVIDIA's CUDA wheels** (both workers) are under NVIDIA's own licence. They are a runtime dependency of
  torch, not vendored. Should the README say that running the GPU workers means accepting NVIDIA's terms?
- **`microsoft/wavlm-base-plus-sv`**: the card seems to state no licence and to point to microsoft/unilm's MIT
  licence (BELIEVE, weakly). Someone with Hugging Face access should read the card at the pinned revision
  before a release. The Whisper, Qwen and wav2vec2 licences need the same read; all are BELIEVE.
- **Design text proposed** (the lead's to write; I did not edit `docs/design.md`):
  - §17.3: "When the sha256 sent does not match, the error gives the file's own sha256 only if the file is a
    WAV. The WAV check comes before the sha256 check, so a caller cannot learn the hash of any other file."
  - §17.9: "A program the operator commands run (uv) is looked up only in the folders on `PATH`, never in the
    working folder."
  - §17.2 (or a new item): "The store, the models folder, the worker projects and the configuration file must
    be writable only by the operator's account: the provenance list and `allow_sha256` are the synthetic-voice
    rule's trust anchors, and workers load the models and the venvs."

## Next

- **S3 (Low).** Refuse the pinned tokenizers' other added tokens (`<tts_pad>`, `<think>` …) in spoken text,
  hints and descriptions. This changes the text rules' sha256, so it needs a design decision. It extends
  WP34's existing follow-up for the description to cue text and hints.
- **S4 (Low; Medium on a shared machine).** `doctor` should warn when the store root, `models_root`, the
  configuration file or a worker project is writable by another account. This needs Windows access-list code
  in `narration.platform`, with a Windows test.

  name with `FILE_FLAG_OPEN_REPARSE_POINT`. Windows only.
