## Done
- `.github/workflows/ci.yml`: one workflow, five jobs. It runs on pushes to `main` and `wp/**` and on every
  pull request.
  - **lint** (ubuntu): `uv sync --locked`, `uv run ruff check --output-format=github` (inline annotations),
    `uv run ruff format --check --diff`.
  - **types** (ubuntu): `uv run basedpyright`.
  - **tests** (matrix `windows-latest`, `ubuntu-latest`, `fail-fast: false`): `uv sync --locked`, `uv run pytest`.
    pyproject's addopts already deselect `model`, `gpu`, `evidence` and `slow`.
  - **tracked** (ubuntu, `fetch-depth: 0`): `python tools/check_tracked.py` on the checked-out tree. On a
    PR that tree is the merge result. Then `python tools/check_tracked.py --commits <range>`:
    - on a PR, the range is `base.sha..head.sha`;
    - on a push, it is `before..sha`;
    - on a push that created the branch (an all-zero `before`) or rewrote it (`before` is not in the
      history), it is `origin/main..sha`.
  - **schemas** (ubuntu): if `tests/contracts` does not exist, it prints a `::notice` and passes.
    Otherwise it runs `uv run pytest -m "not model and not gpu and not evidence and not slow" -k schema tests/contracts`.
- Every action is pinned by full commit SHA with a version comment. I looked the SHAs up again after the
  restart, on 2026-09-26. All three tags are lightweight, so each SHA is the release commit itself.
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1)
  - `actions/setup-python@5fda3b95a4ea91299a34e894583c3862153e4b97` (v7.0.0)
  - `astral-sh/setup-uv@c18668ad3cf93ea998bef934396af7bb5c839dc7` (v10.2.0). Its cache is on, keyed on
    `uv.lock` (`cache-dependency-glob: uv.lock`).
- Other settings:
  - top-level `permissions: contents: read`;
  - no secrets;
  - `persist-credentials: false` on every checkout;
  - `concurrency` cancels a superseded run on the same PR or branch, but never on `main`;
  - timeouts: lint 10 min, types 10, tests 20, tracked 5, schemas 10.
- Nothing in CI needs a GPU, a model, the bakeoff or a secret.

## Decisions made (and why)
- **Python comes from `actions/setup-python` 3.12, and uv never downloads one**
  (`UV_PYTHON=3.12`, `UV_PYTHON_DOWNLOADS=never`). It mirrors AGENTS.md §2: contributors use an
  installed 3.12 and never a uv-managed one. A missing interpreter then fails loudly instead of
  being fetched.
  - The patch version floats within 3.12, which only gets security fixes now.
  - Reverse this if patch drift ever changes a result. Then pin `python-version: "3.12.x"`.
- **uv is pinned to 0.10.10**, the version that wrote `uv.lock` and the one AGENTS.md names. uv's
  latest is 0.12.x now.
  - setup-uv v10.2.0 carries the known checksums for 0.10.10 on both runner platforms and verifies the
    download.
- **`UV_LOCKED=1` workflow-wide**, besides the explicit `uv sync --locked`, so no uv command in CI can
  re-lock.
- **Commit messages on a new or rewritten branch.** The brief said to skip an all-zero `before`. I check
  `origin/main..sha` instead: otherwise the first push of every new `wp/**` branch would check no
  messages at all.
- **Only a commit count is logged**, never commit text. Echoing a message could inject `::` workflow
  commands into the log, and `check_tracked.py` itself prints only SHAs and line numbers.
- **Separate jobs, with the three set-up steps repeated in each, not YAML anchors.** GitHub's anchor
  support is recent, and I could not verify it without pushing. The cost is five copies of each SHA to
  bump together.
- **No `PYTHONUTF8` or `PYTHONIOENCODING`.** The Windows job should see a user's default encodings, so
  code that forgets `encoding="utf-8"` fails in CI.
- **Once `tests/contracts` exists, the schemas job must select at least one test.** Pytest's exit 5 fails
  the job, so the schema checks can't silently disappear.
- **`fail-fast: false`** on the test matrix, so a Windows failure doesn't hide the Linux result, and
  vice versa.
- **A `wp/**` branch with an open PR runs CI twice** (push and pull_request, in different concurrency
  groups). I accepted that, as the brief asks for both triggers.
- **No `CONTRIBUTING.md` section.** The file doesn't exist on this branch or on `main` (WP02 writes it),
  so the paragraph is below for the lead to place. No `CHANGELOG.md` line: that file doesn't exist yet,
  and CI is not a change a package user notices.

### Paragraph for CONTRIBUTING.md ("CI")
> Every push to `main` or a `wp/**` branch, and every pull request, runs the CI workflow
> (`.github/workflows/ci.yml`) on GitHub Actions. **lint** runs `ruff check` and `ruff format --check`;
> **types** runs `basedpyright`; **tests** runs the default pytest suite (no `model`, `gpu`, `evidence` or
> `slow` tests) on Windows and Linux with Python 3.12, installed with `uv sync --locked`, so a stale
> `uv.lock` fails; **tracked** runs `tools/check_tracked.py` over the files and over the commit messages
> being pushed or proposed (no local paths, no audio, weights or databases); **schemas** checks that the
> published tool schemas contain no `$ref` and that every `outputSchema` is an object. Nothing in CI needs
> a GPU, a model or a secret. To reproduce a job locally, run the same `uv run …` command from the
> workflow file.
