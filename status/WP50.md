## Done

  Design 5.16 section 14 gives it `never`, and the design handler already raises it with `retake_trigger`

  - `is_retake_trigger` treated every fail as a trigger regardless of the table. It now follows the retake

- **`narration-admin install`'s stop message** (`admin/install.py`): "The next job starts a fresh daemon" is
  now "Jobs queued before this stop wait for the next start: `narration-admin daemon start`, or the next
  submit_job while [daemon] autostart is on. That daemon runs the whole queue." (section 4.1). The module
  docstring says the same. `tests/admin/test_install.py` pins the new text.
- **The flaky daemon test was a real bug in the supervisor, not in the test** (`daemon/supervisor.py`).
  - The race: the daemon's control loop calls `supervisor.poll()` every `poll_s` while the runner's thread
    starts a worker. The slot publishes its client before `start()`, so that `close()` and `kill_all()` can
    reach a starting worker. A worker that cannot start exits before `hello`. If `poll` saw the dead process
    before the client's stdout reader had read its exit code (the reader first waits for the process, then up
    to 1 s for stderr to catch up), `poll` counted a crash and closed the client. `hello` then failed as "the
    fake worker was closed" with no exit code, so `start()` could no longer tell a broken venv
    (`EXIT_START_FAILED`, which is `BACKEND_NOT_INSTALLED`) from a crash. The fake runner retried, lost the
    race again, and failed the job `INTERNAL` after 2 failures. The job engine is exposed the same way, and
    the slot was never marked failed for good.
  - KNOW: the failing CI log (run 36413692901) shows the supervisor's "the qwen worker (pid …) exited; it
    starts again when next needed" warning (the line `poll` writes) before each of the two failures.
  - The fix: the slot records that its client is starting (`_Slot.starting`), and `poll` leaves it to its
    start. `close()` and `kill_all()` still reach a starting worker.
  - The regression test `tests/daemon/test_supervisor.py::test_a_poll_during_a_failed_start_leaves_it_backend_not_installed_s14`
    holds the client's report of the exit back until a poll has run, so the race is taken every time. It
    failed on the commit before the fix (ee8ce85, run 36438575387) 31 of 31 times on Linux and on Windows,
    with the exact error CI had seen: `WorkerCrashed('the fake worker was closed')`.
- **WP47's F3, done** (contracts 1.6.10): each take reports its own speaking share, its speaking time over

## Decisions made (and why)
- `is_retake_trigger` still treats a fail of an unknown code as a trigger. A future flag missing from the table
  should err towards a retake, as it always did.
- F3's share is null, not 1.0, when the silences were not measured. The ladder's `speaking_share` counts
  such a take as 1.0 for estimates. A per-take report should say "not measured" rather than assume no pause.
- The race is fixed in the supervisor, not in the test. The daemon could really report the wrong code, and
  with a real broken venv, the job engine would retry a worker it should have given up on.
