## Decisions made (and why)
- **The seed's byte layout.** §10.3 leaves the concatenation open, so it is fixed here: UTF-8 parts
  joined by NUL, digest bytes 0–3 big-endian, masked to 31 bits (interfaces.KeyBuilder).
- **Versioned key schemas.** Keys carry schema ids the design does not name
  (`narration.delivery-key/v1`, `narration.analysis-key/v1`, `narration.measurement-key/v1`), so every
  hashed object is versioned.
- **What the engine profile hash leaves out:** `snapshot_dir` (a local path), `observed`, and `canary`
  (DC-3). The canary pin now carries the canary clip. The Store keeps the clip under `engines/`, where it
  is never collected.
- **Absent versus null.** An optional field that is unset (`X | None = None`) is left out of the JSON. A
  nullable field (`X | None`, no default) is always present. The schemas follow the same rule.
  - This is what makes `Error` and `Flag` match §7.2's fragments.
  - It also makes `fit` absent without `scene_seconds` (§12), while an unplaced cue keeps `start_s: null`
    (§11.2).
- **Take alignment view.** §7.5 and App. B disagree on the alignment's shape. The take in `get_results`
  uses `TakeAlignment` (§7.5: `cross_check` is a string, `max_disagreement_s` sits beside it, and there
  are no cues). The analysis sidecar keeps `Alignment` (App. B).
- **`TakeResult.flags`** holds the delivery flags and the per-job flags (`SPK_OUTLIER`,
  `CANARY_MISMATCH`, `RETAKEN`). They are never part of the cached verdict (§11.1).
- **Store is the only channel** between processes (§4, no sockets). It holds the daemon's status
  (`run/daemon.json`) and a command queue (`release_gpu`, `stop`, `stop_now`). It also has:
  - `claim_job` and `update_job(expect_status=…)` as compare-and-set, so a cancel is never reverted;
  - `jobs_created_since`, for the rate cap across processes.
- **Unsupported platform.** Non-Windows calls raise `UnsupportedPlatform`, a `DAEMON_UNAVAILABLE` error
  that is not retryable. No new §14 code was needed.
- **Cached takes keep their embedding.** `AnalysisRecord.embedding` lets consistency be computed for
  cached takes without loading a model.
- **Material.** The material records and `MaterialLoader` are defined here. The loader
  (`narration.material`) is WP18's follow-up.
- **Review findings rejected by the verifier, and not applied:**
  - bounds on `[limits]` and the ladder (§16 gives none);
  - merging `[workers] env` over the defaults (the daemon always sets the offline variables; now
    documented);
  - a typed `SubmitRequest`/`JobResults` (the input and output schemas fix those layouts);
  - `Store.wait_for_job` (polling `get_job` suffices).
- **Hint.note** was added: §9.1 lists it, and it enters no key.
- **The voice profile** drops jitter and shimmer for CPPS (DC-1). Speaking rate is null without a
  transcript.
- **A failure inside a tool call** is an `INTERNAL` tool error. JSON-RPC -32603 is used only outside a
  call (ADR 0001).
- **`voice_hash`'s `model` is the Base repo id** (`names.MODEL_QWEN_BASE`), never a revision or an engine
  profile id, so a voice keeps its hash across a re-pin (§10.1, §15). `voice_hash` applies NFC itself.
- **`Alignment.model` and `revision` are optional.** App. B's analysis sidecar names the aligner in
  `versions.aligner_method`, and a sidecar in that shape must load. The service always sets them.
- **`JobRecord.request` is a dict**, validated by the tool's input schema. There are no typed request
  records (the docstring named some that were never made).
- **`EngineProfile.tier` is not hashed.** It is the repeat test's outcome on this machine, set after the
  pin, like `observed` and `canary`.
- **`QaInputs.hints` are the hints used in the segment**, the set the analysis key covers, never the
  request's whole list (§11.1: a verdict depends only on inputs its key covers).
