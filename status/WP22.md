  declared need on a shared GPU; with it, 3.6 GB stays reserved between ops. Results unchanged (the acceptance passes). The release never raises: a failure is logged, so it
  cannot turn an op's `GPU_OOM` into `INTERNAL` (review item 1).

## Decisions made (and why)
- WavLM pinned at `main` (`feb593a6…`): the evidence loaded its .bin; the same tensors as refs/pr/8; the
  snapshot is complete (config and preprocessor config).
- A snapshot of another model is `BACKEND_NOT_INSTALLED` (as the aligner, WP15), not qwen3's `INVALID_REQUEST`.
- The shared snapshot check covers the fake and the QA worker; the `qwen3` worker keeps its own check of
  `model` (WP20's code, not touched here; the same codes and fields).
- The allocator's cache is returned after every GPU op (above): a declared need is only honest if the
  process's footprint stays within it.
- CI: no worker-qa job (the brief: only if torch-free, else report). Most QA tests need torch (the tiny
  snapshots, the loaders, the worker process). A torch-free job could run the rest (test_voice, test_asr's pure
  tests, test_gpu_manners, the contract tests that need no load) from a venv synced with
  `uv sync --no-install-package torch --no-install-package torchaudio`, at the cost of syncing librosa, numba,
  scipy and matplotlib on each runner; not added. The shared snapshot-reference contract test does run in CI,
  through the fake.

## How WP32 should take `vram_need_mb` = 11500 for the QA group
- **A named constant of the service, not a measurement per machine.** In the module that assembles `QaPins`
  (`installed_engine`), e.g. `QA_VRAM_NEED_MB: Final = 11_500`, with a docstring citing
  `spikes/h-i-qa-load/README.md` ("What this gives the engine profile"). It is the scheduler's admission figure
  for the QA group (section 4: load only when NVML free ≥ need + 1 GB, so 12.5 GB free).
- **Not the `load` reply's `vram_mb`.** That is what the load reserved (3606 MB, the resident models), not the
  ops' peak; the need is about three times it.
- **What it covers:** the whole group's largest footprint, CUDA context included: Whisper-large-v3 fp16 eager at
  its pinned revision, five beams unconditioned with word times (ADR 0004), WavLM-base-plus-sv fp32 at `main`
  with 60 s windows (DC-15), and the cache release after each op. It holds for a take of any length. The
  aligner and profiling run on the CPU and add nothing.
- **When it must change:** any change to those (a model revision, dtype, attention, decoding, word times,
  `WINDOW_S`, the release) needs spike h re-run and the constant updated with it. A cheap guard: a unit test in
  WP32 that the QA pins name exactly the revisions and settings the constant was measured with (Whisper
  `06f233fe…`, WavLM `feb593a6…`, `narration_worker_qa.asr.DECODING`, `narration_worker_qa.sv.WINDOW_S` = 60),
  so a change there fails a test until someone re-measures.
- **Not hashed** (DC-16, approved): a re-measurement changes the constant without changing any profile hash.
