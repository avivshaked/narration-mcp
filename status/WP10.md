## Decisions made (and why)
1. **Whitespace** is tab, line feed, carriage return, and the Unicode `White_Space` characters that are not
   control characters (space, no-break, thin, ideographic and so on). Every other Cc character is refused,
   VT, FF and NEL included (lead ruling).
2. **Format characters (Cf) are not refused.** This covers zero-width space and joiners, bidi marks, the
   BOM and the soft hyphen. Each one is a `symbol` warning whose message gives the code point (`U+200B`),
   and the text is spoken as sent. Why: callers paste them without seeing them, so refusing would be
   hostile, while a warning with the code point lets the caller find them. `strict_text` still refuses
   them, like any warning.
3. **Lone surrogates (Cs) are refused** (`TEXT_REFUSED`, reason `surrogate`). The design does not name them.
   They are not text: they cannot be encoded as UTF-8, so they could not be hashed into a key or sent to a
   worker, and they would surface as an `INTERNAL` error.
4. **Hint respellings and terms are sanitised too.** A respelling goes to the engine, so markup in it is the
   injection §17 item 6 forbids. Terms and respellings are put in canonical form. A term that is only
   whitespace, an empty respelling (it would silence the term), and a repeated term (§9.1: one request
   never mixes two renderings) are each `INVALID_ARGUMENT` with `field` `hints[i].term` or
   `hints[i].respell`.
5. **Hint matching.** A term must stand as a whole word: it is bounded by the start or end of the cue, by
   U+0020, or by Unicode punctuation (P*: the hyphen and both apostrophes). Symbols, digits and combining
   marks do not bound a word. Longer terms go first, and terms of equal length go in code-point order, so
   the result never depends on the order of the request. A term with no respelling still claims its places
   and is recorded with `respell: null`, so the longest-first rule governs it as well. `hints_applied` is
   sorted by offset, and each offset is into the cue's spoken text.
6. **`TERM_SPLIT_ACROSS_CUES`** is raised once for each place a term would match across a boundary, even
   when the same term applies inside another cue. It is a segment-level flag with `cue` set to the first
   cue, and `details` holds `{term, cues: [first, last], offset}`, where `offset` is into the first cue's
   spoken text.
7. **The checks look at the engine text** (the spoken text with respellings in place), and they report
   offsets in the spoken text. A respelled term's own characters raise nothing: `R2-D2` respelled
   `Artoo-Deetoo` gets no digit warning. The respelling itself is checked; a finding inside it is reported
   at the term's offset, with `details.respell_of` naming the term. Why: the warning says "the engine will
   read it as it reads digits", which is true only of what the engine is given. Without this, a caller who
   did what the service asks (a hint) would be refused under `strict_text`. **Needs the lead's OK** (see
   Questions).
8. **Tokens of findings.** A `digit` or `symbol` finding is the whole run of that class (`2026`, `&&`, one
   emoji ZWJ sequence), located at its first character. A `unit_like` or `letter` finding is the word. A
   digit is reported as `digit` only, never also as `symbol`. A combining mark takes the class of the
   character before it, so `q̇` and Devanagari text are letters, and a mark after a space is a symbol.
9. **Word** (the single definition, `narration.text.words`): a whitespace-separated token with its leading
   and trailing Unicode punctuation (P*) set aside. A token of punctuation only, such as a lone `—`, is
   not a word and takes no index. WP14 and WP15 should use this function so that word indices agree
   (see Questions).
10. **Exact spans.** A span is refused only when an end falls strictly inside a word's core. An end may
    fall in the whitespace or punctuation around a word, so `seven`, `seven.` and `(forty)` all pass, and
    so does a start inside a leading bracket. A span must satisfy `start < end ≤ len(cue as sent)` and
    cover at least one word. Overlaps are refused on the span that starts later. `start` and `end` are
    echoed as sent; `words` is `[first, end)`.
11. **Unit list** (`rules.UNIT_SYMBOLS`): every SI prefix (24, with micro as both U+00B5 and U+03BC),
    applied to the SI base units, the special-named derived units, and L, l, t, eV and Wh. It also holds
    the unprefixed symbols of two or more characters and common abbreviations (mph, ft, lb, psi, dB, rpm,
    °C, km/h, KB/MB/GB and so on). **Exclusions**, as ordinary words in that case:
    - lower case: in, am, as, at, hm, dam, dag, dal, al, au;
    - title case: Ah, Pa, Ms, Mm, El, Em, Et;
    - everyday all-caps initialisms: TV, PC, PA, PS, MA, MC, MS, TA, QA, YA, EV, PT.

    A test checks that every exclusion removes a generated entry. MW, GW, TB and the like stay in the
    list. **A judgement call** (see Questions).
12. **`strict_text`** refuses only on severity `warn`: `WRITTEN_FORM_TOKEN` other than `letter` (info),
    and `TERM_SPLIT_ACROSS_CUES`. It never refuses on `SEGMENT_TOO_LONG`.
13. **Offender format** in `error.details.offenders`. There are two shapes:
    - markup and control characters: `{field, segment_id?, cue?, text, offset, reason:
      markup|control|surrogate, codepoints}`. `offset` is into the text as sent in that `field`.
    - `strict_text`: `{field, segment_id, cue, code, severity, token, kind, offset[, respell_of]}`, or
      `{…, term, cues, offset}` for a split term.

    `error.field` is the first offender's field. Field paths are `segments[i].cues[j].text`,
    `segments[i].text`, `segments[i].cues[j].exact[k]`, `segments[i].segment_id` and `hints[i].respell`.
14. **A cue that is only whitespace** is `INVALID_ARGUMENT`: it would put a double space into the join.
15. **Rules hash** (`TextChecksInfo.rules_sha256`) is 64 bare hex characters, like every other `*_sha256`
    field. It is the sha256 of the RFC 8785 JSON of `rules.rules_document(refuse)`, which includes the
    Unicode version and the configured `refuse` list. A test pins the value for text-1.1.0, so a rule
    change cannot happen silently. It uses `rfc8785` directly, because WP12's `narration.keys` is not
    built yet; the canonical form is the same. `TextPipeline(config)` raises `ConfigError` when
    `text.checks` is not `names.TEXT_CHECKS_VERSION`, or when `refuse` holds an empty string.
16. **`SEGMENT_TOO_LONG`** is the helper `segment_too_long(segment, max_segment_chars=…,
    max_segment_seconds=…)`, outside the protocol because it needs the voice's measurement. Its message is
    §7.3's, word for word. `plan_segment` takes an optional keyword `field_prefix`, which stays compatible
    with the protocol.
17. **Lint.** A trigger is a maximal run of letters, marks and digits (with an apostrophe allowed between
    two of them), matched against the list after case folding, with `’` read as `'`. `dont` is the only
    form without an apostrophe, because `cant` and `wont` are English words. `non` counts only when a
    hyphen and a letter follow it (U+2010 and U+2011 are accepted as hyphens).

    The phrase starts at the trigger and runs:
    - to the end of the hyphenated word the trigger is part of (`non-breathy`, `no-nonsense`);
    - otherwise through the next word;
    - never across punctuation.

    A longer phrase from the suggestion table (`no movie-trailer delivery`) takes precedence. `note` is
    always set, to the text of the §7.6 example. Offsets are code points into the description as sent;
    it is not normalised.
18. The `regex` package is not used: `unicodedata` and plain scanning were enough, so the rules depend
    only on Python's Unicode version, which is part of the hash.
