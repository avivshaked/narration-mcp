## Done
- **The seam in the job engine** (`2c67cd7`, `refactor(jobs)`, typing only): `EngineCore.phase` and
  `Stages.qwen_need/ready/_ensure` take an `ActiveRun` protocol (job id, phase, message, the Qwen engine
  profile, the prepared worker) instead of `state.JobRun`. `JobRun` satisfies it unchanged. A design job's run
  satisfies it too, so VoiceDesign loads through the same stage, with the same residency, fingerprint check
  and canary gate, instead of a copy. No behaviour, key or hash changes.
- **The `design` job kind** (`narration.design.handler`, `6456312`; the GPU acceptance test `21e2d15`):
  - **Seeds** (`narration.design.seeds`): `narration-design-seed/v1`. The seed of candidate *i* is the first
    4 bytes (big-endian, masked to 31 bits) of sha256 over `scheme \0 sha256(description) \0
    sha256(spoken design text) \0 i`. It comes from the request alone: the design id is not in it, so the
    same request designs the same voices. A golden value pins it.
  - **The design text is spoken as sent**: the text pipeline's NFC and whitespace form, with no hints. A
    rule change since submit is refused at `open` (`TEXT_REFUSED`, `field: design_text`).
  - **Rendering**: every candidate is designed in one VoiceDesign load, through `Stages.ready` (the canary
    gate runs after the load). The `design` op gets the verbatim description, the spoken text, the language,
    the seed, `max_new_tokens` (the DC-4 per-call cap `call_cap`) and the out path. The load payload is
    `qwen_load_payload`, so every audio-changing setting is explicit.
  - **Then one candidate at a time**: the exact-transcript check (Whisper `transcribe`, then
    `measure.transcript.check_transcript`), then the profile (the `profile` op with the transcript, so it
    has a speaking rate), then **provenance first, then the candidate**: `add_provenance` (idempotent), and
    then `put_candidate`. A stopped or given-back job resumes at the first unpublished candidate. Candidates
    already published are reused, and their provenance entries are re-added.
  - **Flags per candidate**, published with it (`Candidate.flags`): `TOKEN_CAP_HIT` (fail), `WER_HIGH` (fail;
    the message names `REF_TEXT_MISMATCH`, with `details` heard, wer, word errors and words), `CLIP_TOO_LONG`
    (fail), and `CANARY_MISMATCH` as **info** when the design engine passed its gate on `similarity_pass` in
    the `bit_exact` tier (the lead's decision). A fail flag ends the job `needs_attention`, and the candidate
    is still published, so the person can listen to it.
  - **Failures** (`narration.design.work.Pieces`): a missing engine pin or model is `BACKEND_NOT_INSTALLED`
    with a hint; `GPU_OOM` is retried once after the engine's wait, and then `GPU_UNAVAILABLE` (retryable,
    `retry_after_s`); a crash or timeout is retried once, and then `INTERNAL` (retryable); a lost worker state
    reloads; a full disk is `STORE_FULL`, publishing included. Every error has its `field` where one applies,
    and a `hint`.
    Scratch is removed on every ending.
- **The `profile` job kind** (`narration.design.profile`): any WAV that is readable, by path and sha256 (no
  synthetic rule, no 30 s limit). The audio is staged into the job's own scratch folder through `stage_clip`,
  with errors re-fielded to `audio.*` and hinted, and goes with the job. It runs on a QA worker **loaded with no model, on the CPU** (the QA
  worker's `load` accepts empty `models`; after that, only `f0` and `profile` run), or on the resident QA
  group as it is, with no load. No transcript is sent, so `speaking_rate_wpm` is null. The same bytes are
  answered from the profile cache. Silent audio is `UNSUPPORTED_AUDIO` (`field: audio.path`).
- **Wiring**: both kinds are in `engine.installed.more_handlers` and in the backend's `RUNNABLE_KINDS`.
  `get_results` for a design gives each candidate with its own `flags`. `tests/backend/test_steps.py`'s
  "not installed" test now covers only `audition_pronunciation`.

## Decisions made (and why)
- **Reuse `Stages.ready` for VoiceDesign** through `ActiveRun`, rather than a second load path. The canary
  gate, the fingerprint check and residency then behave exactly as for generation.
- **A candidate is published only after its checks.** Provenance is appended before the candidate file, so
  a published candidate is always on the list. A candidate that fails a check is still published, with
  the fail flag, because the person decides.
- **The shared profile of a clip's bytes has no speaking rate.** The candidate's copy adds the rate from
  its known transcript. So `profile_voice` on the same bytes gives the same answer however it was first
  profiled (a key from the request and the bytes only).
- **`profile_voice` never takes the GPU.** It uses a no-model QA load on the CPU, unless a QA group is
  already resident.
- **Seeds exclude the design id** (§10.3: the segment id is not in a seed). This makes design deterministic
  and cacheable per request.

## Follow-ups (recorded, not done; the lead's call)
- **No cache for a repeated design or profile** (design F5). An identical `design_voice` after its job completed
  designs again under a new design id (about 2 min on the GPU); the seeds make the voices the same. And
  `profile_voice` on bytes already profiled still queues a job, which the handler answers from the cache when
  it is claimed. Fix: at submit, create a `profile` job completed when `get_profile` has the bytes (as
  `measure_voice` does), and look up a completed design with the same identity.
- **No `WER_HIGH` warn level** (design F6). A candidate one word off its text (WER about 0.03 on the default
  text) carries no flag; the fail rule is `measure_voice`'s (WER over 0.06 with 2 errors). Fix: `WER_HIGH` warn
  at the `DEFAULT_PROFILE` warn rule, which leaves the outcome `all_passed`.
- **A batch design that gives way loses its unpublished clips** (engine F3). They are designed again on resume,
  with the same seeds, so only GPU time is lost (up to four designs and a model swap). Noted in the handler's
  docstring. Fix if it matters: keep designed clips across a give-back, checked by sha256 and seed.
