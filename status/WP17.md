## Review follow-ups (the independent review: MERGE-WITH-FOLLOWUPS), all fixed, each with tests
1. **Cancellation no longer interrupts a tool mid-call** (medium). SDK 2.2.0's default peer cancel mode
   cancels the handler, so `notifications/cancelled` could cut `submit_job` and the others off between
   two backend awaits.
   - Every tool's backend call now runs in `anyio.CancelScope(shield=True)`.
   - The exception is `get_job` (`server.INTERRUPTIBLE_TOOLS`), whose wait is what cancellation ends.
   - The SDK still drops the reply to a cancelled request.
   - Tests: `test_a_cancelled_call_still_finishes_its_backend_work_s5` covers `submit_job`, `cancel_job`
     and `design_voice`, in both eras. The call is held at a gate, cancelled, and released. The backend
     then finishes it, and the request is never answered. All 6 cases fail with the shield removed
     (checked).
2. **Non-finite numbers are refused in results** (medium-low). NaN or infinity anywhere in a result, a
   tool error's `details` included, becomes `INTERNAL`.
   - The error lists each path with its rule (`finite`, or `type` when a typed field fails first), never
     the value.
   - Code: `results.non_finite_paths` plus the output check.
   - Tests: `test_a_non_finite_number_in_a_result_is_an_internal_tool_error_s14` and
     `test_non_finite_paths_finds_every_nan_and_infinity_s14`.
3. **An integer field no longer accepts `2.0`** (low-medium). The input and output validators are now
   `validation.ExactValidator`: Draft 2020-12 with three rules made exact.
   - `integer` is an int, never a float.
   - `number` is finite, so `wait_s: NaN` and `scene_seconds: NaN` are refused.
   - A pattern's final `$` is the end of the string, as in ECMA-262. Python's `re.search` would let
     `job_… + "\n"` pass `id_schema_pattern`.
   - Test: `test_integers_numbers_and_patterns_are_exact_s14` (8 cases).
4. **`LIMIT_EXCEEDED`**, per the lead's ruling. A `maxItems` or `maxLength` failure on `segments`, `cues`,
   `hints` or `text` is `LIMIT_EXCEEDED`.
   - It is not retryable, and carries the field and a hint to split or shorten.
   - Every other schema failure stays `INVALID_ARGUMENT`: `voice.transcript`, `description`, `label`,
     `variants`, `attempts`.
   - Tests: `test_a_request_size_bound_is_limit_exceeded_with_a_hint_to_split_s14` (7 cases) and
     `test_other_size_bounds_stay_invalid_argument_s14` (5 cases).
5. **Resource ids are checked for shape.** Every template variable must pass `names.is_id` for its kind
   (`job_id`, `design_id`, `take_id`, `voice_hash`).
   - The URI must be exactly the template filled with those ids: no percent-encoding, query or fragment.
   - A malformed id is -32602, and the backend is never called.
   - Test: `test_a_malformed_resource_id_is_invalid_params_before_the_backend_s7_7`, 10 URIs in both eras:
     `%2e%2e%2f%2e%2e`, `C:%5CWindows`, a trailing `\n` and `%0A`, a percent-encoded valid id, upper-case
     hex, a lower-case ULID, a query, `..`, and an upper-case hash.
   - `test_every_resource_template_variable_is_an_id_kind_s7_7` pins the mapping.
- **Contracts 1.1 to 1.5:**
  - The fake uses real-shaped ids (`job_` plus a ULID, and a ULID design id).
  - A reused `idempotency_key` (DC-6) passes through as the backend's `INVALID_ARGUMENT` on
    `idempotency_key`: `test_a_reused_idempotency_key_is_the_backends_invalid_argument_s7_3`.
  - The closed `controls.pace`, nullable loudness and `ExactResult.words` need no front-end code. The
    schema tests cover them through the contract schemas.

## Decisions made (and why)
- **Shielding covers every tool but `get_job`.** A cancellation must not leave a half-done write, such as
  a job row without its plan. `get_job` is read-only, and its wait is what cancellation is for (section 5).
  - The cost: a shielded backend call also runs to its end when the connection closes. So WP36's calls
    other than `get_job`'s wait must be bounded (store work), never open-ended waits.
- **Resource URIs must be canonical.** A valid id written with percent-encoding is refused. This leaves
  one way to write each URI, so the backend (WP36) never has to decode one.
- **The exact validator is used for inputs and outputs alike**, so the front-end checks what the schema
  says. The SDK client's own check is laxer (it accepts `2.0` as an integer), so this only catches more
  backend bugs, never fewer.
- **Choosing among several failures.** When a request fails several rules, the error's code follows the
  failure it reports (the shallowest). So an unknown field reports `INVALID_ARGUMENT` even if the request
  is also oversized. `details.errors` lists them all.
- **Earlier decisions stand**:
  - the backoff rule on every tool that is not read-only;
  - `INTERNAL` is not retryable and never carries exception text;
  - progress through `ctx.session.report_progress`;
  - resource-read errors are -32602 or -32603;
  - list caching is 1 h;
  - the stdio test uses a test-only server module.
