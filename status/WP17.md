   component of `validation._sort_key`, so any other failure is reported first, with its own code and hint.
   - Test: `test_limit_exceeded_only_when_every_failure_is_a_size_bound_s14`, the lead's four repros.
     - 201 segments plus `segments[0].style` gives `INVALID_ARGUMENT` on `segments[0].style`, with the
       section 3.3 hint.
     - 201 segments plus `text_mode: "written"` gives `INVALID_ARGUMENT` on `text_mode`, with the section
       9.2 hint.
     - 501 hints plus `label: 5` gives `INVALID_ARGUMENT` on `label`.
     - 201 segments plus `options: 5` gives `INVALID_ARGUMENT` on `options`.
   - Every case still lists the `maxItems` failure in `details.errors`.
   - With the old sort key, 3 of the 4 fail (checked). The `options` case already passed before, as the
     re-review said.
2. **A URI built by RFC 6570 is read.** `server.resolve_resource` (it replaces `match_resource`) accepts
   two spellings of the same well-formed ids.
   - The first is the template filled with the raw ids, which is the canonical URI.
   - The second is the template's RFC 6570 expansion (`UriTemplate.expand`), which writes a
     `voice_hash`'s `:` as `%3A`.
   - The backend always gets the canonical URI. The reply's `uri` is the one the client asked for.
   - Every other encoding is still -32602 before any lookup: lower-case `%3a`, `%73ha256%3A`, a
     double-encoded `%253A`, and the ten URIs from the first review.
   - Test: `test_a_uri_built_by_the_sdks_rfc_6570_expander_is_read_s7_7`, in both eras. It builds every
     template's URI with the SDK's own expander, asserts `sha256%3A` is on the wire, and checks that the
     backend saw only canonical URIs.
3. **The shield is limited to writes and has a deadline.**
   - Only the tools that write are shielded (`server.SHIELDED_TOOLS`, derived from `read_only` in the
     contract schemas): `release_gpu`, `cancel_job`, `design_voice`, `profile_voice`, `measure_voice`,
     `audition_pronunciation` and `submit_job`.
   - Each runs in `anyio.move_on_after(WRITE_DEADLINE_S, shield=True)`, where `server.WRITE_DEADLINE_S` is
     30.0.
   - Past the deadline the call returns an `INTERNAL` tool error, "the backend did not answer in time"
     (`results.deadline_error`). It is not retryable, its details are `tool`, `deadline_s` and `log`, and
     its hint says to read `get_server_status` or `get_job` before sending the request again.
   - Tests:
     - `test_only_the_tools_that_write_are_shielded_for_at_most_30_s_s5` pins the set and the constant.
     - `test_the_server_stops_at_once_when_the_client_leaves_during_a_read_s5` covers `get_job` (blocked
       wait), `check_text` and `get_results` (gated). The client's stream is closed mid-call, and
       `server.run` returns in under 2 s without the backend passing the gate.
     - `test_a_blocked_write_holds_the_server_only_until_its_deadline_s5` gates `submit_job` with a 0.5 s
       deadline. `server.run` returns between 0.25 s and 3 s.
     - `test_a_write_past_its_deadline_is_an_internal_tool_error_s5` checks the error, and that the server
       keeps serving.
     - `test_a_cancelled_call_still_finishes_its_backend_work_s5` (first review) still passes.
   - A regression in the three hang-prone tests hangs rather than fails, so each is marked
     `timeout(60)`. Without the deadline, the blocked-write test fails on that timeout (checked).
4. **Every ECMA `$` anchor is the end of the string.** `validation.ecma_anchors` rewrites every `$` that
   is unescaped and outside a character class to `\Z`. A `]` right after `[` or `[^` is a literal, as in
   Python.
   - Tests, in the new `tests/mcp/test_validation.py` (17 tests):
     - the rewrite of `a$|b$`, `(a$)`, `^a$`, `[$]`, `[^$]$`, `[]$]`, `[^]$]x$`, `\$`, `\\$` and `a\\\$`;
     - what `a$|b$`, `(a$)`, `[$]`, `\$` and `\\$` match and refuse, including a trailing newline;
     - `ExactValidator` refusing `"a\n"` against `^(a$|b$)`.

## First review follow-ups (MERGE-WITH-FOLLOWUPS), fixed in the previous round
1. **Cancellation.**
   - Superseded by re-review item 3: a cancelled write still finishes its backend work, now for up to 30 s.
   - Tests: `test_a_cancelled_call_still_finishes_its_backend_work_s5` covers `submit_job`, `cancel_job`

2. **Non-finite numbers.** NaN or infinity anywhere in a result, a tool error's `details` included,
   becomes `INTERNAL`. The error lists paths, never values (`results.non_finite_paths`).
3. **Exact validation.** `validation.ExactValidator` is used for inputs and outputs alike. It is Draft
   2020-12 with three rules made exact:
   - an integer is never a float;
   - a number is finite;
   - a pattern's `$` anchors are ECMA's, now in any position.
4. **`LIMIT_EXCEEDED`.** A `maxItems` or `maxLength` failure on `segments`, `cues`, `hints` or `text` is
   `LIMIT_EXCEEDED`, with a hint to split or shorten. The code applies only when it is the sole kind of
   failure (re-review item 1).
5. **Resource ids.** Every template variable must pass `names.is_id` for its kind before any lookup.
6. **Contracts 1.1 to 1.5.**
   - The fake uses real-shaped ids.
   - DC-6's reused `idempotency_key` passes through as the backend's `INVALID_ARGUMENT`.

## Decisions made (and why)
- **`WRITE_DEADLINE_S` = 30 s is an obligation on WP36.** Every backend call of a tool in `SHIELDED_TOOLS`
  must finish well inside it.
  - Such a call is store work or a command to the daemon, never an open-ended wait.
  - The constant also bounds how long a closing connection waits for a write in flight.
  - The value is a module constant, and a parameter of `build_front_end` for tests. It is not a config key,
    since the design has none.
- **A write past the deadline is `INTERNAL` and not retryable.** Its outcome is unknown, since the backend
  may have written part of it. The hint says to read `get_server_status` (and `get_job`) first, rather
  than invite a blind retry.
- **Two spellings of a resource URI are accepted: the raw one and the RFC 6570 one.** Conforming clients
  build the RFC 6570 form. Accepting exactly those two keeps a single decoding rule, the SDK's.
  - Anything else is still refused.
  - The backend (WP36) never decodes: it gets the canonical URI.
- **Which failure is reported.** A failure that is not a size bound comes first, then the shallowest. So
  `LIMIT_EXCEEDED`, which tells the caller to split the request, is used only when splitting would fix
  every failure.
- **Earlier decisions stand**:
  - one validator for inputs and outputs;
  - the backoff rule on every tool that is not read-only;
  - `INTERNAL` is not retryable and never carries exception text;
  - progress through `ctx.session.report_progress`;
  - resource-read errors are -32602 or -32603;
  - list caching is 1 h;
  - the stdio test uses a test-only server module.
