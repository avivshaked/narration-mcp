## Done
- **The rate, one rule for measurement and QA** (`src/narration/qa/pace.py`, `names.PACE_METHOD` =
  `narration.pace/articulation-cps@1`). Pace = spoken characters per second of **speaking time**: the voiced
  span less every silence inside it of at least `MIN_PAUSE_S` = 0.25 s (13 or more 20 ms frames). Shorter
  silences (a stop's closure) stay in. The ladder reads QA's `articulation_cps`, so the curve and a take's pace
  are one quantity by construction.
- **Where the pauses come from:** the signal stage's own speech-frame mask, the same rule as the voiced span:
  `post/pipeline.measure_signal` now reports `SignalStats.internal_silences_s`. It exists for every take with a
  voiced span. If a `SignalStats` has none (None: built without them), the rate is over the whole voiced span,
  `pause_s` is null, and the flag's `details.basis` says `voiced_span`.
- **QA** (`qa/checks.py`): `PACE_FAST`/`PACE_SLOW` judged on `articulation_cps` against `expected_cps`, with the
  same `tol`, `pace_tol_min` floor and warn factors; the hotfix's no-fail default is kept (DC-19): a fast take
  only warns unless a profile sets `pace_fail_tol_factor`. Details: `articulation_cps`,
  `expected_articulation_cps`, `tol`, the three lines, `pause_s`, `basis`. QA profile **`default.v5`**.
- **Measurement** (`measure/ladder.py`, `measure/handler.py`): trend, `tol` (the same relative seed spread, now
  of cps), rung judgement and curve on the new rate; `speaking_share` (median over the band's takes of speaking
  time / voiced span) for estimates.
- **Keys:** `narration.measurement-key/v2` adds `pace_method`; `narration.measurement/v2` for the record. The
  store reads a measurement of another schema as absent (`get_measurement` None, `measurements_of` skips it):
  `VOICE_NOT_MEASURED` until `measure_voice` measures again, which replaces it. Until then its takes stay
  pinned, so the re-measure finds them. No render, delivery or engine-profile input changed; nothing under
  `workers/`, `material/canary/` or `engine/profile.py` changed.
- **Every other user:** duration estimates (`jobs/plan.estimated_audio_s` → `qa.pace.estimated_seconds`:
  characters / expected cps / speaking share; this feeds `check_text`, `dry_run`, progress `total_s`, the
  queue's estimates and §12's prediction), `get_results` (`PaceValue.articulation_cps`), the report line
  (`qa/report.py`), `tests/measure/run_acceptance.py`. `narration-admin` prints no pace (KNOW: grep). Tool
  texts: no change needed (`descriptions.py` never names words per minute; KNOW: grep). `schemas.py`: one
  line, `_PACE` gains `articulation_cps`.
- **Merged origin/main twice** (the hotfix PR #42 with PR #40; then PR #37). One conflict (`pace_flags`),

## Contract change requests
Approved by the lead: the Pace model in cps, new metric and detail fields, the QA profile id. The fields
beyond that, each with why it is needed and what breaks without it (the lead decides at review):
- `SignalStats.internal_silences_s`: QA receives the audio only as `SignalStats`, so the pause time must come
  through it. Without it QA cannot take pauses out, and the rate falls back to the voiced span, the rule the
  lead's correction rejected.
- `MEASUREMENT_SCHEMA` → `narration.measurement/v2`: the guard that an old record is never read. Without it,
  a `/v1` record would either fail `from_json` (renamed fields: the store would raise, and every tool that
  looks the voice up would answer `INTERNAL`, not `VOICE_NOT_MEASURED`) or, had the names been kept, be read
  as cps.
- `names.PACE_METHOD` (and `pace_method` in the key): the pace-method version the lead asked for. Without it
  a later change to the rule (the 0.25 s, say) would not re-measure a voice.
- `MEASUREMENT_KEY_SCHEMA` → `/v2`: the key object gained a member. **Redundant**: `pace_method` changes the
  hash anyway. Nothing breaks without it; it only marks the object's new shape.
- `Pace.speaking_share`: duration estimates (`check_text`'s `est_duration_s`, `dry_run`, progress `total_s`,
  the queue's drain estimate, §12's prediction) must include pauses. Without it they would count speaking
  time only and run short by the pause share (KNOW on the fake: 3–5 %; BELIEVE on real paragraphs: more,
  with a pause per sentence). The alternative is a second curve of voiced-span cps.
- `Pace.method`: says in `measurement.json` which rule its numbers are in; code reads it only in tests.
  **Optional**: nothing breaks without it; a reader of the JSON loses the unit.
- `LadderSeed.cps` (was `wpm`), with `spoken_cps` and `wpm` kept as information: the ladder table shows the
  pace each seed was judged on. Without `cps` the table would show only words per minute, which no longer
  decides a rung. `spoken_cps` and `wpm` are information only (optional).
- `QaMetrics.articulation_cps`, `expected_articulation_cps`, `pause_s`: `articulation_cps` is what the ladder
  reads from QA (the "one rule" guarantee); the expected value is what it was judged against; `pause_s`
  records which basis was used (the lead asked for that). Without them the ladder would have to recompute the
  rate outside QA.
- `PaceValue.articulation_cps`: `get_results` shows the pace that was judged and the pace expected. Without
  it a caller sees only words per minute, which no longer decides a flag.
- Outside this package's area: `store/store.py` (the `/v1` skip, 4 lines and a docstring paragraph) and
  `post/pipeline.py` (the silences list).

## Questions for the lead / owner
- **A falling trend ends long rungs early (BELIEVE a risk for real voices; KNOW on the fake).** The ladder
  extends the band's straight line to longer rungs, as §3.2 says. In words per minute the line rose with the
  corpus's word lengths; in characters per second a real voice's line should be near flat, and noise in a
  4-point fit can tilt it down. Extended from 300 to 560 characters, a slope of −0.3 cps per 100 characters
  lowers the limit by about 5 %, so a long rung must then be within about +5 % of the band's pace instead of
  +10 %. The fake shows the extreme (a two-rung band fitting −1.7 per 100). Options: judge rungs above the
  band against max(trend at the length, the trend at the band's top), or floor the slope at 0. That is a §3.2
  change (a DC), so I did not make it.
- The 0.25 s pause threshold is ASSUME: the classifier refused my attempt to measure pause lengths on the
  bake-off's clone takes (PII handling), so the first evidence will be the owner's voice measured again. On the
  fake, clause gaps (0.25 s written) measure 0.24 s and stay in speaking time; sentence gaps (0.4 s) measure
  0.38–0.40 s and come out (KNOW, computed).
- The owner's `narration.toml` `[qa] profile = "default.v3"`: no code reads that key (KNOW: grep), so it does
  not matter; `doctor` could check it later.
