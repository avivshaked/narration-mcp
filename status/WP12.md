## Done
- `narration.keys` implements `KeyBuilder`:
  - RFC 8785 canonical JSON, and `sha256:` keys over objects built member by member, each with a `schema`
    member;
  - `voice_hash`, the measurement key, `render_key`, `delivery_key` and `analysis_key`;
  - the seed exactly as section 10.3 pins it;
  - `rn_`/`tk_`/`an_` ids;
  - ULID job and design ids.
- `voice_hash` accepts only `names.MODEL_QWEN_BASE` and `names.LANGUAGE`, and applies NFC itself.
- `narration.store` implements `Store` (`NarrationStore`):
  - SQLite in WAL mode with a recorded schema version;
  - content-addressed publishing, with a folder staged and renamed in one write transaction together
    with its index row;
  - read-only immutable files;
  - leases, the job queue, `gc` and `verify`;
  - confinement (section 17.2) through the injected `Platform`.

## Decisions made (and why)
- The first round's decisions stand, except where the review changed them:
  - relative sidecar paths;
  - measurement folders named by hex;
  - the first publish of a key wins;
  - one measurement per (voice, engine profile);
  - `create_job` dedupe, now with DC-6;
  - the `analysis_key` hint set;
  - candidate folders;
  - `put_profile(None)`;
  - re-entrant claims;
  - `update_job` NOT_FOUND;
  - a 1-day grace period;
  - `synchronous=FULL`.
- **gc holds the write lock while it renames.** The renames are fast. A path that stays locked costs up
  to about 1 s of retries before it is listed as an error and skipped. gc is an operator command.
- **A leftover `.trash-` name** (a removal that failed after the commit) is collected as a leftover once
  it is past the grace period.
- **Returning the caller's audio makes it writable again**, as the caller had it before `move_into` made
  it read-only.
- **The DC-6 hint** is a sentence, as other hints are: "Use a new key for a different request."

## Questions for the lead / owner
1. **F2 and `from_config`.** The configuration has no aligner method id. `[alignment]` names the `model`,
   but not the pinned revision or the snap parameters, and the method id covers all three. So
   `from_config` cannot derive the id: it takes `alignment_method_id` as a keyword, and the caller that
   pins the aligner (WP30/WP32) passes it. Is that acceptable, or should `Config` gain the method id?
2. **Another trailing-newline check, outside WP12.** `src/narration/config.py` still validates
   `[voices] allow_sha256` with `re.compile(r"^[0-9a-f]{64}$").match`, so `"<hex>\n"` passes. That file
   is lead-owned, so I left it alone. The fix is `fullmatch`.
3. **The delivery golden value changed** because `post` is in the key (contracts 1.3). If WP13 or anyone
   else hard-codes a take id, they need the new value. I found no copy of the old one in the repo.
