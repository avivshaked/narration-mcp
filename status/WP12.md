## Done
- `narration.keys` implements `KeyBuilder`:
  - RFC 8785 canonical JSON (`rfc8785`), and `sha256:` keys over objects built member by member, each with
    a `schema` member;
  - `voice_hash`, the measurement key, `render_key`, `delivery_key` and `analysis_key`;
  - the seed exactly as section 10.3 pins it;
  - `rn_`/`tk_`/`an_` + 16 hex ids;
  - ULID job and design ids from a stdlib, monotonic, thread-safe generator (`narration.keys.ulid`).
- `voice_hash` follows 6af1475:
  - `model` must be `names.MODEL_QWEN_BASE` and `language` must be `names.LANGUAGE`. Anything else is
    refused with a `ValueError`, not hashed.
  - The transcript is put in NFC inside `voice_hash`, so callers pass it as received. A test pins that the
    NFD and NFC spellings give one hash.
- `narration.store` implements `Store` as `NarrationStore(root, platform, *, retention, clock)` or
  `NarrationStore.from_config(config, platform)`:
  - Database:
    - SQLite in WAL mode with `synchronous=FULL`;
    - `PRAGMA user_version` plus a `schema_migrations` table;
    - a database from a newer schema is refused (`StoreSchemaError`).
  - Paths:
    - content-addressed, with two-hex shards;
    - confined twice: by the id grammar, then by the realpath staying under the root's realpath, plus
      `Platform.check_store_path` (section 17.2).
  - Publishing:
    - a folder is staged under `.staging-*` and renamed in the same write transaction as its index row;
    - a file is written as `.tmp-*` and then `os.replace`d;
    - immutable files are read-only before they appear under their names.
  - Leases have tokens (`SqliteLease`: renew, release, `LeaseLostError`), and `wait_for` polls with
    backoff.
  - Jobs:
    - `create_job` is idempotent;
    - `claim_job` and `claim_next_job` work in priority order;
    - `update_job` compare-and-sets with `expect_status`;
    - `jobs_created_since`.
  - Every by-id getter, `analyses_of`, `measurements_of`, `put_profile(record, pictures_dir)` and
    `put_candidate(candidate, clip_audio)`.
  - Engine profiles:
    - pinned hashes are immutable;
    - `current_engine_profile` per `EngineKind`;
    - the canary clip.
  - Alignment benchmarks, and the current one.
  - Provenance: SQLite plus `provenance.jsonl`.
  - Daemon status and daemon commands.
  - `touch`.
  - `gc`:
    - a dry run by default;
    - retention by `last_used_at`;
    - crash leftovers and orphans after a grace period;
    - old scratch;
    - expired leases.
  - `verify` rehashes every indexed file and runs SQLite's integrity check.
- There are no OS imports. OS-specific checks go through the injected `Platform`.
- The module docstrings state that the store is stateless: it holds caches of work done and the service's
  own records, nothing a caller chose.
- Fixed after the rebase: `publish_temp` retries a replace that fails because a reader has the old file
  open. On Windows that is "access denied" until the reader closes the file. It retries 20 times, about 1 s
  in all.
- There is a CHANGELOG line for each of keys and store.

## Decisions made (and why)
- **Sidecar paths**:
  - Records on disk and in SQLite hold paths relative to the store root. The API returns absolute paths.
  - Why: a store folder can be moved or restored and still verify.
- **Measurement folders** are named by the voice hash's hex without the `sha256:` prefix.
  - Why: `:` is not legal in a Windows file name.
- **First publish wins** for a render, take or analysis key.
  - A second `put_*` of an existing key keeps the first bytes and returns the stored record.
  - Why: a key names one result, and a take id a caller has recorded must keep naming the same audio.
- **One measurement per (voice, engine profile)**, in `measurements/<voice hex>/<engine profile id>/`.
  - The same measurement key again is a no-op.
  - A different key replaces the old measurement: a new corpus or new ladder settings.
- **`create_job` dedupe**:
  - It first matches an active job (queued, running or cancelling) of the same kind with the same
    `idempotency_key`, then one with the same `request_sha256`.
  - A request whose earlier job has finished makes a new job.
- **`analysis_key`** sorts `hints_qa`, and each hint's `asr_aliases`.
  - Why: they are a set, and the order in a request must not change a cached verdict.
  - Nothing else is normalised.
- **`voice_hash` refuses** a model other than `MODEL_QWEN_BASE` and a language other than `LANGUAGE`,
  rather than hashing them.
  - Why: a wrong value would silently fork a voice's measurements.
  - This is easy to relax if a later version supports more.
- **`current_alignment_benchmark`** is the most recently published benchmark.
- **Candidate folders** are `designs/<design_id>/<index>/`.
- **`put_profile(record, None)`** requires the record's picture fields to be empty.
  - A new profile version removes the old pictures.
- **Moves need their source inside the store**: `put_*` moves audio only from a source inside the store
  root (`scratch/`).
  - Why: the store never takes custody of a file outside its root, and the move stays on one volume.
- **Claims by the same holder are re-entrant**: claiming again renews the lease.
- **`update_job`** on an unknown job raises `NotFoundError` (`NOT_FOUND`). It returns None only when
  `expect_status` does not match.
- **`gc` grace period** for crash leftovers, orphans and scratch is 1 day (`DEFAULT_GRACE_S`).
  - Why: a live writer's temporary file is never collected.
  - An active job is never collected.
- **`synchronous=FULL`** in WAL mode, and **busy timeout** 30 s.
- **A pinned engine profile's `hash` is immutable**: the same id with another hash raises
  `StoreIntegrityError`.
  - The unhashed parts (`observed`, `tier`, the canary) may be updated.
  - The store compares the `hash` field and does not compute it.

## Questions for the lead / owner
1. **Reusing an `idempotency_key` for a different request.** Today `create_job` returns the active job with
   that key, as the contract says. Should it be refused instead, as `INVALID_ARGUMENT` on
   `idempotency_key`? That would be safer for a caller who reuses a key by mistake. It needs a one-line
   contract decision; the code change is small.
2. **The platform stand-in.** Until WP19 (`narration.platform`) lands, the store's tests use a stand-in
   `Platform` (`tests/store/standin.py`) with a real `check_store_path`: reserved names, a trailing dot or
   space, links and junctions. When WP19 merges, the tests could also run against the real platform.
3. **Process note.** Earlier in this WP, before the `python -m` instruction, I ran tools through the venv
   launchers (`uv run pytest`, `uv run basedpyright`). Since then, everything has gone through
   `uv run --frozen python -m …`.
